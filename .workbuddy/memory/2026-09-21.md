### 踩到的坑（都已在代码里修掉）

1. `ON CONFLICT DO UPDATE command cannot affect row a second time`（SQLSTATE 21000）：
   同一批 INSERT 里有相同冲突键就会炸（故事正文有重复）。→ `bulk.go` 里先按冲突键去重。
2. sqlc 默认生成 `database/sql` 版 DBTX，pgxpool 满足不了 → 必须 `sql_package: pgx/v5`。
3. sqlc 把 `migrations/` 整个目录当 schema 时会被 down 脚本的 DROP 打乱 → 只列 up 文件。
4. **改了代码要确认老进程真死了**：老 api.exe 仍占着 18080，新进程 bind 失败（日志里
   `Only one usage of each socket address`），冒烟打到的还是旧二进制。用 `tasklist` 找到
   `api.exe` 的 PID 再 `taskkill /F /PID`，别只按名字杀。
   把 api.log 写进 `server/tmp/api.log` 能第一时间看到 bind 失败。
5. 冒烟脚本里带中文的路径要 `urllib.parse.quote`（http.client 只收 ASCII）。
