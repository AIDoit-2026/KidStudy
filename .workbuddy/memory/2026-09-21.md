### 踩到的坑

1. **`knowledge_points.ref_id` 在 M2 从未回填**（只补了反向的 hanzi.kp_id），
   组卷的 JOIN 永远匹配不到，语文/英语会话返回「组不出题目」。
   → 新增导入步骤 `refs` 幂等回填（`go run ./cmd/importer -only refs`），
   本次回填汉字 8103、英语词 1802。**导入顺序决定哪些引用必须事后补，写完导入器要回头查一遍。**
2. 孩子的 `stage_code` 是语文阶段，拿它过滤数学知识点（M1–M5）一条都选不出来
   → 新学候选的 stage 过滤只对语文生效（`stageFor()`）。
3. `interval_hours = 0.17` 小时其实是 10.2 分钟，`ceil(0.17*60)` 显示成 11 分钟
   → 答错间隔单独定义 `WrongReappearAfter = 10 * time.Minute`，展示值从实际时长反推。
4. sqlc 类型覆盖的 `db_type` 必须写 **`pg_catalog.numeric`**，只写 `numeric` 不生效
   （生成出来还是 pgtype.Numeric）。`pg_catalog.date` 同理，但 date 那次没生效就留用 pgtype.Date。
5. **本地起服务要用 `run_in_background=true`**：用 `(go run ./cmd/api &)` 起的子进程
   会随那次 Bash 调用结束被回收，冒烟时连不上（WinError 10061）。

### 关键设计决定

- 数学与打印同源：逐题种子用 `Derive(seed, i)` 而非全局递增，中途增删题目不漂移。
- 答案 `answer_key` 与题面 `question_snapshot` 分列，任何读接口都不返回答案。
- 主观项（trace/say）`is_correct = null`，不写 answer_logs、不动掌握度 → 家长评分不污染客观正确率。
- 跨模块只走 service 接口：practice → mastery/content，practice+mastery → children.EnsureOwned。

### 踩到的坑

1. **偏差算出 -0.33 天**：pgx 把 `date` 扫进来给的是 UTC 零点，本机 +08，本地零点直接相减
   正好差 8 小时。抽 `daysBetween` 把两边归一到同一时区零点（rollup 与报表共用）。
2. **compare 混入他人孩子回 500**：归属失败返回裸 `error`，全局映射认不出 `apperr` 按 500 兜。
   必须回 `apperr.NotFound`（并保持 404 而非 403 的一致约定）。
3. **math 题面在 `item.question.prompt` 下**，不在 item 顶层 —— 冒烟脚本取题面要按这个层级。
4. **sqlc 类型推断两个坑**（M4 又踩一次）：
   - `count(*) FILTER (...)::float8 / count(*)::float8` 被推成 int32 → 比率一律 Go 侧算；
   - `max(timestamptz)` / `min(date)` 被推成 `interface{}` → 显式 `COALESCE(...)::类型` 兜底；
   - `AT TIME ZONE` 表达式旁边的 `sqlc.arg(stat_date)` 会被推成 timestamptz → 统一加 `::date`。
5. 报表的 `Trend` 依赖 `''` 合计行：原先 M3 只在「无分学科」时才写该行 → 改为无条件写。

### 关键设计决定

- 日汇总独立进程而非 API 内定时器（长任务不占请求连接池）。
- 同一 (孩子,日期,学科) 是覆盖式重算，与 M3 的会话增量不冲突，可反复跑（实测 rows 恒定）。
- 成就规则放 `badges.rule` jsonb，评测器在 Go 侧解释 —— 调门槛不用发版。

- 多孩对比默认按「学习日序号」对齐、只并列不排名，note 里明写，前端不再自行解读。

### 关键实现决定

- **渲染只有一套**：预览 HTML = 家长浏览器 Ctrl+P = chromedp 出的 PDF，是同一份 HTML 字符串。
- **PDF 渲染放 worker**：API 的 `POST /pdf` 只置 `queued` 返回 202；claim 用
  `FOR UPDATE SKIP LOCKED`，超时未完成的按 `-print-stale` 退回队列。
- **`page_count` 读 PDF 真实页树**（`/Type /Page` 计数 vs 各级 `/Count` 取最大，互校），
  不拿排版估算冒充；估算只作 `planned_pages` 单独展示。
- **mark-done 一个事务四步**（标记完成 + 建会话 + 写掌握度 + 清专项指派），
  幂等靠 `marked_done_at IS NULL`，重复提交返回 `already_done`。
- 补录以 payload 快照为准；请求里不在快照的 kp 直接忽略（防跨任务回填进度）。
- **renderer 懒启动**：API 也构造但不初始化（不拉 Chromium），本机没浏览器不拖垮 API。
- `print → report` 一条只读边（周报模板复用 Overview/Trend/Suggestions），方向仍单向。

### 踩到的坑

1. `sqlc.arg(template_code)` 被推成 `[]byte` → 查询里显式 `::text`。
2. mathgen 下沉对拍时**手写 golden 抄错两处期望值** → 改成从对拍实际输出取真值再固化。
3. 迁移 `-migrate` 在沙箱里被信号打断（实际已应用）→ 用 psql 复核 `schema_migrations` 再决定是否重跑。
4. **本地起服务务必确认老进程已死**：老 api.exe 占着 18080 时新进程 bind 失败，curl 却仍打旧二进制。
5. `match_lines` 对新号默认 `range=recent` 会 422（可配对素材 <4 组）—— 正确行为，冒烟需指定阶段。
