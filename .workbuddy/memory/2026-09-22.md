### 做法：凭据外置 + 消除 CWD 依赖
- 用一次性脚本 `server/tmp/refactor_smoke.py` 把凭据值**直接从脚本抽到 `server/.env`**
  （`SMOKE_ACCOUNT` / `SMOKE_PASSWORD` / `SMOKE_PIN`），值全程不经过对话输出；
  `.env.example` 补三行占位 + 注释说明各自用途。
- PIN 的提取规则踩了一次坑：要**只认同一行同时有 `/auth/pin` 与 `expect=200` 的调用**，
  否则会把「非法格式 `abc`（422）」当成正确 PIN；故意错的 `0000`（401）同理必须保留字面量。
- 新增 `server/tests/smoke/_common.py`：按 `__file__` 推导 `SERVER_ROOT` / `TMP_DIR` / `ENV_PATH`，
  提供 `env(key, default=None)`。各脚本删掉自己那份 `env()` 定义，改为 `from _common import ...`。
  于是 **任意 CWD 都能跑**（旧写法 `open(".env")`、`dirname(dirname(__file__))` 迁完就指错）。
- `smoke_m4/m5` 的 `subprocess.run(..., cwd=".")` 改成 `cwd=SERVER_ROOT`：
  Go 侧用 `godotenv.Load()`，它是从**当前工作目录**找 `.env` 的，不固定 CWD 换个目录跑就会缺配置。
- `./tmp/worker.exe`、`./tmp/importer.exe` 改成 `os.path.join(TMP_DIR, ...)`。

## UI 验收脚本脱敏并入库（server/tests/ui）

### 凭据反查推翻上一轮的判断
上一轮靠**键名**扫描（`password|pin|...`），既误报又漏报。这次改成**拿 .env 真实值当基准反查**
（`server/tmp/find_creds.py`），才拿到准确清单：`ui_setup.py` 3 处，`ui/flow*.json` **32 处**。
上一轮只认出 flow4/4b/6 —— 既漏了 flow1/2/5/7，又把 flow4 里 `input[type=password]`
这种 selector 字样当成了凭据。
**教训：安全扫描要拿真实值当基准，不能靠模式的键名猜。**

### 做法
- 一次性脚本 `server/tmp/refactor_ui.py`：从 `.env` 读值直接替换，**明文全程不经过对话输出**；
  每个文件替换后先 `json.loads` 校验，不合法就中止。
- 三类值参数化：凭据 → `${SMOKE_*}`；前端地址 → `${BASE_URL}`；
  截图目录（原为硬编码 `E:/Personal/...`）→ `${OUT_DIR}`。
- 新增 `run.py`：渲染后把 JSON 从 **stdin** 喂给 `agent-browser batch`（凭据不进命令行）。
- `_common.py` 从 `tests/smoke/` **上移到 `tests/`**，smoke 与 ui 共用；6 个 smoke 脚本补 `sys.path`。

### 踩到的三个坑（都是 run.py 自己引入的，已修）
1. **Windows 路径反斜杠破坏 JSON**：`${OUT_DIR}` 渲染成 `E:\Personal\...`，`\P`/`\s`/`\u`
   全是非法转义 → agent-browser 整批拒收，只报一句 `invalid escape at line N column M`。
   修法：替换值统一 `json.dumps(...)[1:-1]` 转义，并在启动浏览器**前**先 `json.loads` 本地校验。
2. **等 stdout EOF 会挂死**：agent-browser 拉起的 Chrome 继承了管道，agent-browser 退出后管道
   仍开着 → `for line in proc.stdout` / `communicate()` 永远等不到 EOF。最初那个
   「跑 3 分 38 秒、毫无输出」就是这个原因（不是流程卡住）。
   修法：读输出放独立线程，主线程只 `proc.wait()`；跑完默认 `close --all` 回收。
3. 顺带：`bail` 默认关（continue all），所以**退出码 0 不代表每条断言都成立** ——
   必须看输出里的 `active`/`clicked-*` 实际值。

## 追加：flow4 / flow6 打通（长等待 + 日额度两处根因）

上一轮 flow4/flow6 一直 exit=1，这轮定位到**两个独立根因**，都已修掉：

### 根因 1：agent-browser 单条命令 25 秒硬上限
查 agent-browser README 确认：**标准操作（含 wait）默认超时 25 秒**，且受 CLI 侧
30 秒 IPC 读超时约束（`AGENT_BROWSER_DEFAULT_TIMEOUT` 调高到 30s 以上会 EAGAIN）。
所以 `wait <sel> --timeout 420000` 根本等不住 —— 25 秒后报
`Failed to read: A connection attempt failed...`（CDP 空闲断连），打 `✗` 并把退出码拖成非 0。
实测确认：批处理里单条命令失败**不会中断整批**（后续 `wait`/`eval` 照跑），但退出码变 1。

修法：**长等待改由 host 侧轮询**。`run.py` 重写为
1. 同一 `--session`（实测 `--session` 跨 CLI 调用**保页面/Cookie/localStorage**）跑前半批；
2. host 每 3 秒 `agent-browser --session <S> eval "!!document.querySelector('<sel>')"`，
   命中即返回（真早退，不白等满预算，也**不产生任何假失败**）；
3. 同一 `--session` 跑后半批。
`["wait","<ms>"]`（ms>25s）同理改成 host 分片盲等。流程 JSON 无需改结构 ——
`--timeout N` 在 run.py 里被解释成「host 侧轮询预算」。`--dry-run` 会打印分段计划。
另加：某批非 0 就直接停（不再傻等后面的长等待）。

顺手修的坑：
- `shutil.which("agent-browser")` 命中 npm 的 `.CMD` shim，`node <.cmd>` 报语法错 ——
  改成反推 `<node 目录>/node_modules/agent-browser/bin/agent-browser.js`（向上找 3 层）。
- 轮询耗时原来按「轮询次数 × 间隔」估算，漏了每次 eval 的进程开销（~1s/次），
  报告值偏低（300s 显示成 228s）→ 改用 `time.monotonic()` 真实计时。

### 根因 2：孤儿会话把当日时长顶爆
`TodayUsedSeconds` 对 `ended_at IS NULL` 的会话按 `now - started_at` 计，且**没有会话过期
回收**（只有 StartSession/FinishSession，worker 里没有 expire）。反复跑同一天的验收不断
留下未结束会话 → 当日时长从 66/60 涨到 216/480。`remaining<=0` 时组卷不再排新题、
会话可能起不来，护眼场景被日额度掩盖。

修法：`ui_setup.py` 的每条命令都把 `daily_limit_min` 给到**上限 480**（等同不设闸门），
并在 docstring 写明理由。日额度文案由后端 `planMessage` 承担，不在这几条浏览器流程里验。
