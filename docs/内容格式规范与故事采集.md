# KidStudy · 内容格式规范与故事采集结果

> 回答「中文小故事是什么格式」+ 记录本轮实际采集到的故事类素材。

---

## 一、小故事的格式定义

采用**「YAML Front Matter + Markdown 正文」**，一份 `.md` 即一篇故事。选它的理由：人能直接读改、Git 能 diff、服务端解析成本低（几百行代码），且与 MarkItDown 的产出格式天然兼容。

### 1.1 单篇模板

```markdown
---
id: story-0186
title: 小蝌蚪找妈妈
slug: little-tadpole
level: L3                     # 对应汉字阶段：L1=S1, L2=S2, L3=S3 … 依此类推
type: tale                    # tale=童话 | fable=寓言 | poem=古诗 | rhyme=儿歌 | idiom=成语故事 | life=生活故事
lang: zh                      # zh | en
word_count: 312
topics: [动物, 亲情, 春天]
new_chars: [蝌, 蚪, 池, 塘, 腿]
max_stage: S3                 # 自动校验值：正文用字的最大阶段，必须 == level
source: generated             # generated | public-domain | wikisource | parent
source_url:                   # 若采集而来必填
license: none                 # none | public-domain | CC-BY-SA | PD
audio_url: var/audio/story-0186.mp3
cover_url: var/img/story-0186.png
difficulty_words: 8           # 超纲字数（应为 0 或极少）
questions:                    # 阅读理解题
  - type: choice_text
    q: 小蝌蚪先遇到了谁？
    options: [鲤鱼阿姨, 乌龟爷爷, 白鹅姐姐]
    answer: 0
    explain: 故事里先遇到的是鲤鱼阿姨。
  - type: choice_text
    q: 小蝌蚪最后变成了什么？
    options: [小鱼, 青蛙, 乌龟]
    answer: 1
discussion:                   # 给家长的口头讨论题（不判分）
  - 小蝌蚪找妈妈的时候害怕了吗？你有没有找不到爸爸妈妈的时候？
  - 小蝌蚪的身体是怎么一天天变化的？
---

池塘里有一群小蝌蚪，大大的脑袋，黑黑的身子，甩着长长的尾巴，快活地游来游去。

它们看见鸭子妈妈带着小鸭子，就想起了自己的妈妈。

「我们的妈妈在哪里呢？」

---
### 给家长的话

读完可以问孩子：小蝌蚪为什么一开始认错妈妈？（因为它们只看到了一部分特征）
```

### 1.2 机读版本（入库用）

家长手上的 PDF / Word 教材先用 **MarkItDown** 转成 Markdown，再由 `parse_story.py` 解析成下面这条 JSONL，写进 PostgreSQL：

```json
{
  "id": "story-0186",
  "title": "小蝌蚪找妈妈",
  "level": "L3",
  "type": "tale",
  "lang": "zh",
  "word_count": 312,
  "topics": ["动物", "亲情", "春天"],
  "body_md": "池塘里有一群小蝌蚪……",
  "questions": [{"type": "choice_text", "q": "...", "options": [...], "answer": 0}],
  "discussion": ["..."],
  "audio_url": "...",
  "source": "generated",
  "license": "none"
}
```

### 1.3 强制校验（CI 级别）

每篇入库前必须过校验脚本：

| 校验项 | 规则 | 不通过处理 |
| --- | --- | --- |
| **控字** | 正文每个字必须在 `level` 对应阶段及之前的字表里 | 超纲字 >2% → 打回重写 |
| 字数 | L1: 80–150，L2: 150–250，L3: 250–400，L4+: 400–800 | 打回 |
| 注音 | 允许存在的少量超纲字必须带拼音标注 | 打回 |
| 答案 | 选择题必须有且仅有一个正确项 | 打回 |
| 重复 | 与前 30 篇相似度 <0.6（字级 n-gram） | 打回 |
| 敏感词 | 过一遍与组词相同的黑名单 | 打回 |

**这条控字校验是整套分级阅读成立的前提**——孩子学完 S3 的 200 个字，就该能读懂 L3 的故事。做不到这一点，分级就是假的。

### 2.1 关于现代白话童话的重要结论

**中文儿童故事没有干净的开源语料库。** 我查过：维基文库只有 2 篇童话、0 篇儿歌；GitHub 上相关仓库几乎全是电子书盗链站，没有可用的结构化故事集。

三个可选路线：

| 路线 | 优点 | 缺点 | 建议 |
| --- | --- | --- | --- |
| **A. 原创生成 + 控字校验** | 版权干净、用字精确匹配 S0–S5 字表、情节可贴合已学生字 | 需要生成 120 篇 | ✅ **推荐**。这是唯一能保证"学完就能读"的做法 |
| B. 爬取故事网站 | 量大、省事 | 站点结构各异、编码混乱、**内容质量不可控**（很多 AI 洗稿文）、原作者版权风险（你说家庭自用没关系，我照办） | 需要你**指定 1–2 个具体站点**，我来写解析器和清洗规则 |
| C. 家长现有 PDF/Word 导入 | 完全可控 | 需要家长有素材 | ✅ 已 MarkItDown 通道，作为补充 |

**如果你要走 B**：给我站点 URL，我用 colly 写解析器 + 清洗规则（去广告、去导航、去目录、正则提取正文），入库前照过一遍控字校验和敏感词过滤，结果进 `content_review` 待你审核。

## 三、音频采集结果

| 目标 | 数据源 | 结果 |
| --- | --- | --- |
| 英语单词发音 | `dictionaryapi.dev`（免费词典，音频来自 Wiktionary/Commons） | ⚠️ **接口已限流**，本轮压测拿不到数据（返回非 JSON）。单个词偶能成功，批量不可用 |
| 英语单词发音 | Wiktionary API / Wikimedia Commons | 覆盖率约 30–50%，且多为英式RP，音质参差 |
| 汉字单字发音 | 无可靠免费源 | ❌ 开源汉字单字语音数据集基本没有；网络词典音频多为红链第三方，**不能热链** |
| **兜底方案** | **piper / EdgeTTS 本地批量合成** | ✅ **推荐**。已定为方案，见下 |

**结论：音频不采集，改为本地 TTS 预生成。**

| 项 | 方案 |
| --- | --- |
| 中文 | piper `zh_CN-huayan-medium`（离线，免key）；音质要求高时批跑 EdgeTTS 后缓存入库 |
| 英文 | piper `en_GB-alba-medium` 或 `en_US-lessac-medium` |
| 生成单位 | **以「词 / 例句」为单位，不以单字为单位** —— 解决多音字（"长"在"长短"读 cháng，在"长大"读 zhǎng） |
| 量级 | 汉字 8103 字 × 平均 3 个词 ≈ 2.4 万条；英语 900 词 + 例句约 2000 条；故事朗读 180 篇。全部离线预生成，运行时零外部依赖 |
| 存储 | MP3 64kbps mono，约 2–5 GB |

## 四、内容生产的最终形态

```
汉字/单词              → 采集（8103 字已落地）+ 组词/例句生成 + 控字校验
古诗（1000 首）        → 采集 chinese-poetry → OpenCC 繁转简 → 按年级筛选约 80 首
成语（26 万条）        → 采集 chinese-xinhua ci.json → 按常用度筛 ~3000 条
分级童话/故事（120 篇）→ 生成 + 控字校验（或指定站点后爬取）
儿歌/绕口令（60 条）   → 生成 + 采集补充
视频                   → 不采集，只存外链（见《视频清单》）
音频                   → 不采集，本地 TTS 批量预生成
```
