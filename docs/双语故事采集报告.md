## 五、⚠️ 分级发现：年龄标签与文字难度几乎不相关

用《内容与分级体系设计》的 24 阶段字表做控字校验，结果反直觉：

| 站点年龄标签 | 篇数 | 中位字数 | 中位字阶段 | 98% 覆盖阶段 |
| --- | --- | --- | --- | --- |
| 0-2 岁 | 44 | 36 | **S2** | **G9** |
| 3-5 岁 | 555 | 668 | **S2** | **G7** |
| 6-8 岁 | 231 | 700 | **S2** | **G6** |
| 9-12 岁 | 2 | 700 | **S2** | G9 |

**年龄越大，98% 覆盖阶段反而越低**（0-2 岁 G9 最高，6-8 岁 G6 最低）。

### 为什么会这样

不是数据错了，是两个指标在测不同的东西：

- **中位字阶段全是 S2**（学前第二阶段）—— 说明故事**主体用字非常浅显**，一半以上的字是学前级别。
- **98% 覆盖阶段偏高** —— 因为短文本用字分散。0-2 岁的童谣只有 36 字，像「熊猫宝，圆滚滚。爬呀爬，真开心。」里只要出现一个「滚」「尝」「摇」这类排位靠后的字，整篇就被推到 G9。

**换句话说：98% 覆盖这个判据对短文本会失真**，中位字阶段（S2）才是这批材料的真实难度画像。

### 结论

**站点的年龄标签是按内容成熟度标的（主题、情节、情感复杂度），不是按文字难度标的。** 这批故事的定位就是**家长读给孩子听**——这跟你的使用场景完全一致，所以它们完全可用。

但要注意：文字难度分级只在「孩子自主阅读」时有意义，在「听故事」场景下没有意义。听懂靠的是语音和语境，不是识字量。

如果要做自主阅读材料，**S0–S5 的缺口依然存在**，仍需控字改写管线。

## 六、六个真实的坑

采集过程远比第一故事站曲折，全部记录在此，避免重复踩。

### 6.1 sitemap 每条 URL 重复 4 次

sitemap 里 `/stories/` 路径共 13,312 条，看着很多，**去重后只有 832 篇**。站点生成 sitemap 时把每条重复写了 4 遍。一开始按原始条数估算会以为有 3,328 篇，实际差 4 倍。

### 6.2 sitemap 有未转义实体

72 条 URL 里含 `&apos;`（如 `a-mother&apos;s-story-154`），必须先 `html.unescape` 才能匹配和请求。

### 6.3 Cloudflare 限速：这是本次最大的时间成本

| 策略 | 吞吐 | 结果 |
| --- | --- | --- |
| 并发 10，无延迟 | 0.46 篇/秒 | 12 分钟后近乎停滞 |
| 并发 5 + 0.35s 延迟 | 0.6–0.9 篇/秒 | 改善，但持续跑仍会降速 |
| **超时 40s** | 0.09 篇/秒 | 被挂起请求拖死整个线程池 |
| **超时 18s + 快速失败** | 1.8 篇/秒 | 短暂有效 |
| 并发 2 + 0.8s 延迟 | 0.33 篇/秒 | 慢但稳定，最终靠它收尾 |

**关键发现**：正常请求只要 1.6–2 秒，但持续抓取一段时间后，部分请求会被**挂起**（既不返回也不拒绝）。超时设 40 秒时，这些请求会占满线程池把整体拖垮；改成 18 秒快速失败、让失败项进入补采队列，吞吐反而更高。

已给脚本加 `--delay` 参数控制节奏。

### 6.4 年龄字段提取不到

```python
# 错误：字符集不含数字，匹配不到年龄 slug「3-5」，全部落到 unknown
RE_TYPE = re.compile(r'/category/type/([a-z\-]+)"[^>]*>([^<]+)<')
# 正确
RE_TYPE = re.compile(r'/category/type/([a-z0-9\-]+)"[^>]*>([^<]+)<')
```

### 6.5 短篇被阈值误杀（最重要）

正文阈值最初设 60 字，结果 40 篇里"失败"30 篇。查下来这些是 **0-2 岁组的童谣**：

> 小狗崽，尾巴摇。跑跑跳，真开心。小骨头，啃呀啃。香喷喷，真美味。

只有 58 字。**这批恰恰是最贴合幼儿的内容，差点被整批丢弃。** 阈值降到 15 字后全部补回。

### 6.6 `_index.jsonl` 不可信

它是追加写入的，采集中途中断的批次不留记录（曾出现「索引 81 条 vs 磁盘 390 篇」）。因此**分析脚本改为直接扫描磁盘解析 front matter**，`_pairs.jsonl` 也由分析脚本按 slug 重建，不依赖采集时的索引。

### 附：英文词表太小会误判

`words.jsonl` 只有 1,803 词，拿它当词频表会把绝大多数正常词判成「生僻」。改用 **ECDICT 全量 77 万词**（`var/raw/ecdict.csv`，2.8 秒载入）后才得到合理的难度分布。

## 八、复跑与增量

```bash
# 全量（幂等：已落盘的跳过）
python tools/crawl_beddy.py --workers 2 --delay 0.8

# 站点走 Cloudflare，持续抓取会被挂起；推荐低并发 + 延迟，
# 失败项进入 _failed.jsonl 后统一补采
python tools/crawl_beddy.py --retry-failed --workers 2 --delay 1.0

# 只抓单语 / 冒烟 / 重取 sitemap
python tools/crawl_beddy.py --lang zh
python tools/crawl_beddy.py --limit 50
python tools/crawl_beddy.py --refresh-sitemap

# 重新分析（改了字表或词库后必跑；会重建 _pairs.jsonl）
python tools/analyze_beddy.py
```
