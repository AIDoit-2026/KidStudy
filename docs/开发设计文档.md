## 一、总体架构

### 1.1 部署拓扑（单机起步，先能跑）

```
                 手机 / 平板 / 客厅大屏 / 桌面
                          │ HTTPS
                 ┌────────▼─────────┐
                 │  Caddy（自动 TLS）│  反向代理 + HSTS + 安全头
                 └────────┬─────────┘
          ┌───────────────┼────────────────┐
          │               │                │
   ┌──────▼─────┐  ┌──────▼──────┐  ┌──────▼──────┐
   │ web (静态) │  │ api (Go)    │  │ worker (Go) │
   │ Vite build │  │ chi + pgx   │  │ 导入/汇总/  │
   │            │  │ SSE 扫码登录│  │ PDF/采集    │
   └────────────┘  └──────┬──────┘  └──────┬──────┘
                          │                │
                   ┌──────▼────────────────▼──────┐
                   │  PostgreSQL 16（单机容器）    │
                   └──────────────────────────────┘
                   ┌──────────────────────────────┐
                   │  本地卷 ./var/storage         │
                   │  TTS 音频 / 图片 / PDF / 上传 │
                   └──────────────────────────────┘
```

- 三个 Go 二进制来自**同一份代码**（`cmd/api`、`cmd/worker`、`cmd/importer`），Docker Compose 编排，单机 2C4G 起步。
- **无 Redis**：复习队列、限流、SSE 广播均走 PostgreSQL + 进程内结构（单机够用；未来要横向扩展再引入 Redis，接口预留）。
- **明确不做**：离线/PWA、服务间 RPC、消息队列中间件。

### 1.2 仓库结构（monorepo，路径与已采集资产对齐）

```
KidStudy/
├── docs/                    # 全部设计文档（本文在此）
├── tools/                   # Python 采集/构建脚本（一次性资产生产，不进服务运行时）
├── var/                     # 数据资产（gitignored，仅 var/README.md 入仓）
│   ├── raw/                 # 字/词/阶段/stage_words/ecdict/hwdata …

│   ├── beddy/               # 1,663 篇中英双语故事
│   └── storage/             # 运行期对象存储（音频/PDF/上传）
├── server/                  # Go 后端
├── web/                     # React 前端
└── deploy/                  # docker-compose.yml、Caddyfile、备份脚本
```

## 二、模块划分

### 2.1 后端模块（按功能组织 + 三层）

```
server/
├── cmd/
│   ├── api/main.go          # API 进程：装配、优雅停机
│   ├── worker/main.go       # 定时任务：日汇总、PDF、复习预计算、采集
│   └── importer/main.go     # 一次性内容导入：var/ → DB（M2 使用，可反复重跑）
├── internal/
│   ├── config/              # 环境变量 → Config，启动时校验（缺失/非法即 fail-fast）
│   ├── platform/
│   │   ├── apperr/          # 类型化错误体系（code/http/message/details）
│   │   ├── logger/          # slog JSON Handler + request_id
│   │   ├── server/          # chi 装配、路由注册、优雅停机
│   │   ├── middleware/      # request-id → 日志 → 恢复 → 安全头 → CORS → 限流 → 认证
│   │   ├── postgres/        # pgx 池、Ping、迁移执行入口
│   │   ├── storage/         # 对象存储抽象（local 实现，接口预留 S3）
│   │   └── sse/             # SSE hub（扫码登录广播，进程内 map + 心跳）
│   ├── feature/             # ★ 业务模块，每个模块固定 4 文件
│   │   ├── auth/            # 注册/登录/刷新/登出/PIN/扫码登录
│   │   ├── children/        # 孩子档案与每孩子设置
│   │   ├── content/         # 汉字/组词/英语词句/故事/视频/数学模板 的读取与检索
│   │   ├── practice/        # 今日任务编排、答题会话、判分、数学参数化生成
│   │   ├── mastery/         # 间隔重复调度、错题本、掌握度重置
│   │   ├── report/          # 日报汇总读取、趋势、薄弱点、规则建议、导出
│   │   ├── print/           # 打印模板注册表、题面数据生成、job 管理、PDF 排队
│   │   ├── parent/          # 家长设置、时长/题量/内容开关、纸质练习补录
│   │   ├── review/          # 内容审核队列（爬虫/导入内容 pending → published）
│   │   └── crawl/           # 采集源管理、任务表驱动（worker 侧消费）
│   └── pkg/                 # 纯工具：pagination、timeutil、randx(seed)、pinyin
├── migrations/              # golang-migrate up/down SQL
├── queries/                 # sqlc 查询定义（*.sql）→ 生成 internal/dbgen
├── seeds/                   # 阶段表、数学题型模板、徽章、Dolch 词表等种子 SQL/JSON
└── templates/print/         # 打印 HTML 模板（Go html/template）
```

**每个 feature 固定四件套**

| 文件 | 职责 | 铁律 |
| --- | --- | --- |
| `handler.go` | 解析请求、调用 service、格式化 JSON 响应 | 不写业务规则；不直接碰 SQL |
| `service.go` | 业务规则与编排、事务边界 | **不 import `net/http`**；不感知 JSON |
| `repository.go` | 数据访问（sqlc 生成的 Querier + 少量手写） | 只做查询与持久化；不做决策 |
| `model.go` | 模块内领域结构与 DTO | 领域结构与传输 DTO 分离（`Xxx` vs `XxxDTO`） |

跨模块调用只走 **service 接口 + 构造注入**（例：`practice.Service` 依赖 `mastery.Service`、`content.Service`），禁止 handler 互相调用、禁止 repository 跨模块。

### 2.2 模块职责与依赖一览

| 模块 | 核心职责 | 对外接口（供其他模块调用） | 依赖 |
| --- | --- | --- | --- |
| **auth** | 家长账号、密码/PIN、JWT 签发与刷新、扫码登录状态机、登录审计 | `Authenticate(ctx, token)`、`RequirePIN` | postgres、sse |
| **children** | 孩子档案 CRUD、当前阶段（`stage_code`）、激活/归档 | `GetChild`、`ListChildren` | postgres |
| **content** | 内容读取与检索：汉字（含笔顺）、组词、英语词/句、故事（含双语配对）、视频白名单、数学模板 | `GetHanziByStage`、`PickStory`、`GetMathTemplate` | postgres、storage |
| **practice** | 今日任务编排、会话生命周期、判分、数学题参数化生成、星级计算 | `BuildToday`、`Grade`、`FinishSession` | mastery、content、children |
| **mastery** | 掌握度状态机（简化 SM-2）、复习队列、错题本、难度升降档 | `Schedule`、`ApplyResult`、`ReviewQueue`、`WrongBook` | postgres |
| **report** | 读取 `daily_stats`/`answer_logs`，出趋势、薄弱 TopN、规则建议、CSV/PDF 导出 | `Overview`、`Trend`、`Suggestions` | postgres、content |
| **print** | 打印模板注册表、按参数生成题面数据（可复现 seed）、job 记录、PDF 生成排队 | `CreateJob`、`RenderData` | content、mastery、storage |
| **parent** | 家长设置读写、纸质练习补录（打印后标记完成计入进度） | `GetSettings`、`UpdateSettings` | postgres |
| **review** | 内容审核队列（pending/approved/rejected），下架与申诉 | `Submit`、`Approve`、`Reject` | postgres |
| **crawl** | 采集源配置、任务入队与重试/死信（worker 侧执行，抓取逻辑 Go 侧以 colly 实现，Python 脚本产出的资产走 importer 直入） | `Enqueue`、`RunDueTasks` | postgres |

**依赖方向**（单向，无环）：

```
auth ─┐
      ├─→ children ─→ content ─┐
parent┘                        ├─→ mastery ─→ practice
review ─→ content              │
report ─→ content, mastery     ┘
print ─→ content, mastery, storage
```

### 2.3 前端模块（React 18 + TS + Vite）

```
web/src/
├── app/                     # 应用外壳：路由、QueryClient、错误边界、主题注入
│   ├── router.tsx
│   ├── providers.tsx
│   └── ErrorBoundary.tsx
├── api/                     # ★ 类型化 fetch 客户端（唯一出网口）
│   ├── client.ts            # BaseURL 来自 env；401 自动刷新重试；4xx 不重试 / 5xx 最多 3 次
│   ├── endpoints/           # auth.ts children.ts content.ts practice.ts mastery.ts
│   │                        #   report.ts print.ts parent.ts
│   └── types.ts             # 与后端 DTO 对齐（初期手抄，后期可切 OpenAPI 生成）
├── features/                # 按业务切分，页面 + 组件 + hooks 就近放
│   ├── auth/                # LoginPage、QrLoginPage（SSE）、PinDialog
│   ├── child/               # HomePage(今日任务)、HanziLearn、StoryRead、MathPractice、
│   │                        #   WordCard、VideoPlayer、ReviewPage、AchievementPage
│   ├── parent/              # Dashboard、ChildManage、ReportPage、PrintCenter、
│   │                        #   ContentReview、SettingsPage
│   └── print/               # PrintPreview 路由（无外壳布局）+ 各模板组件
├── components/              # 通用 UI：Button/Card/Modal/StarRating/Confetti(≤300ms)
├── hooks/                   # useSessionTimer(护眼)、useMasteryQuery、usePrintParams
├── stores/                  # Zustand：themeStore(主题/字号/亮度)、childStore(当前孩子)
├── styles/                  # Tailwind + CSS 变量主题 + print.css
└── lib/                     # 工具：时间、拼音注音排版、音频队列
```

- **状态边界**：服务端数据一律 TanStack Query（缓存/失效/重试）；只有「主题、字号、当前孩子、护眼计时器」进 Zustand（可持久化到 localStorage，非敏感）。
- **Token 纪律**：Access Token **只存内存**（模块级变量），Refresh 为 HttpOnly Cookie 由浏览器自动携带；绝不写 localStorage、绝不进 URL。
- **打印路由独立**：`/print/:jobId` 不挂载导航/侧栏，只加载 `print.css`，与屏幕样式物理隔离，避免 Tailwind 屏幕类污染打印。

## 三、数据模型（落地版）

> 约定：所有表 `id uuid pk default gen_random_uuid()`；时间一律 `timestamptz`；软状态用 `status` 枚举文本 + 检查约束；全部时间戳为 UTC，展示层转本地。

### 3.1 身份域

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `parents` | `email citext unique null`、`phone varchar(20) unique null`、`password_hash`、`pin_hash`、`display_name`、`status`、`created_at` | 邮箱/手机二选一，至少一个非空（约束） |
| `children` | `parent_id fk`、`nickname`、`avatar_id`、`birth_ym char(6) null`、`stage_code`（当前学习阶段，默认 `S1`）、`active bool`、`settings jsonb`（覆盖家长默认：时长/题量/字号） | 一个家长独占自己的孩子，不共享 |
| `refresh_tokens` | `parent_id`、`token_hash unique`、`user_agent`、`ip inet`、`expires_at`、`revoked_at`、`replaced_by uuid` | 30 天，轮换时旧令牌标记 `replaced_by`，可撤销 |
| `qr_login_sessions` | `qr_token unique`、`status`（waiting/scanned/confirmed/exchanged/expired/failed）、`creator_ip`、`creator_ua`、`parent_id null`、`scan_count`、`exchange_code_hash null`、`expires_at` | 60 秒过期，一次性兑换；失败 5 次置 failed |
| `login_audit` | `parent_id null`、`event`、`ip`、`ua`、`success`、`created_at` | 登录/扫码/兑换全量审计 |

**索引要点**

```sql
unique (child_id, kp_id) on mastery_records;
index on mastery_records (child_id, next_review_at) where level > 0;
index on hanzi (stage_code, order_in_stage);
index on stories (lang, level_code, suitable, status);
index on stories using gin (to_tsvector('simple', title));  -- 标题模糊检索，M2 后按需
index on en_words (level_code, frq);
unique (child_id, stat_date, subject_code) on daily_stats;
```

- `answer_logs` 数据量大：**M4 落地时改声明式按月分区**（首期先普通表 + `(child_id, created_at)` 索引，避免早期复杂度）。
- 幂等：导入类写入全部带 `content_hash unique`，重跑 importer 用 `ON CONFLICT DO NOTHING/UPDATE`。

## 四、核心交互逻辑（重点）

### 4.1 冷启动：设备 → 登录 → 选孩子（二维码登录时序）

```
桌面/大屏                    API                        手机（已登录家长）
   │  GET /auth/qrcode          │                              │
   │───────────────────────────▶│ 生成 qr_token(60s) + qr_id  │
   │◀────────{qr_token, deep_link}
   │  渲染二维码                 │                              │
   │  GET /auth/qrcode/{t}/events (SSE)                        │
   │───────────────────────────▶│ 注册订阅（心跳 15s）          │
   │                             │                              │ 扫码
   │                             │◀─── POST /auth/qrcode/scan ──│
   │◀── event: scanned {device_info} ──│                        │ 确认页（浏览器+城市+IP段）
   │                             │◀─── POST /qrcode/confirm ────│
   │                             │ 生成一次性 exchange_code(30s) │
   │◀── event: confirmed {exchange_code}
   │  POST /auth/qrcode/exchange  │                             │
   │───────────────────────────▶│ 校验一次性 + IP/UA 绑定       │
   │◀── Access(内存) + Set-Cookie: refresh(HttpOnly,Secure,SameSite=Lax)
   │  GET /children → /select-child → 选宝宝（切换需 PIN）
```

**规则**
- `qr_token` 一次性、60 秒过期；`exchange_code` 30 秒、兑换即焚。
- 扫码端必须已登录；每家长每分钟扫码 ≤5 次；同一 token 失败 5 次即 `failed`。
- SSE 断线：前端 `EventSource` 自带重连；服务端心跳 15s，token 过期推 `expired` 事件并关闭。
- 桌面端拿到 Access 后**存在内存**，刷新页面用 Refresh Cookie 静默换发（`/auth/refresh`），失败回登录页。

### 4.2 今日任务生成（practice 编排）

```
GET /practice/today?childId=
  ├─ 1. 校验：家长设置（可用时段 / 每日上限 / 学科开关）→ 超限返回 remaining_minutes=0 与提示
  ├─ 2. 复习队列：mastery.next_review_at <= now AND level>0
  │       排序：逾期时长 desc, level asc；上限 R_max（默认 20，家长可调）
  ├─ 3. 错题优先：wrong_book_entries 未清除的条目置顶（最多 5）
  ├─ 4. 新学：按 child.stage_code 顺序取「未学(level=0)」的 kp
  │       上限 N_max（默认：语文 6 字 / 数学 2 题型档 / 英语 5 词），家长可调
  ├─ 5. 专项：家长指定 kp（parent_assigned，来自报表建议或打印补录）
  └─ 6. 组卷：为每个 kp 生成题目 → 写 learning_sessions + session_items(快照)
       返回任务卡列表（不返回答案）
```

**题目来源**
- 语文汉字：`choice_text`（听音/看图选字）、`fill_blank`（组词填空）、`trace`（描红，本地判定笔画点位，不计正确率，只记完成）、`order`（组词成句）。
- 数学：`practice` 调 `math_templates` 的参数化生成器，`randx.New(seed)` **确定性随机**，同一 seed 可复现（打印与屏幕同源）。
- 英语：`choice_text`/`choice_image`/`choice_audio`（TTS 音频）/`match`。

**难度自适应**（写进 `mastery` 模块，非 AI 黑盒）
- 同一 kp 连续 3 次正确率 <60% → 降一档（`difficulty-1`），并在报表生成「专项建议」。
- 连续 5 次正确且平均用时低于阈值 → 升一档，上限为当前阶段最高档。

### 4.3 答题与判分（含乐观反馈规则）

```
POST /practice/session/{id}/answer { item_id, answer, used_hint, elapsed_ms }
  ├─ 比对答案（服务端判分，客户端不判）
  ├─ 写 session_items + answer_logs
  ├─ mastery.ApplyResult(kp, correct, used_hint)   ← 见 4.4
  ├─ 返回 { is_correct, correct_answer, explanation, star_delta, streak }
  └─ 错题：写入/更新 wrong_book_entries；会话内 10 分钟后复现一次
```

**反馈原则**：答错不出现红叉与负向文案，展示正确答案 + 一句解释；连对 3 题加一星；跳过不计正确率但计入完成度。

**会话结束** `POST /practice/session/{id}/finish`：计算时长、题量、正确率、星级（≥90% 且无提示 = 3 星 / ≥75% = 2 星 / ≥60% = 1 星），写 `learning_sessions`，触发当日 `daily_stats` 增量更新（同步更新，量小）。

### 4.4 间隔重复（简化 SM-2）与错题本

```
ApplyResult(kp, correct, used_hint):
  r = mastery[kp] (不存在则创建 level=0, ease=2.5)
  if correct:
      r.streak++; r.wrong_streak = 0
      if used_hint: r.ease = max(1.3, r.ease - 0.10)      # 用提示仍算对，但不涨满
      if r.streak >= 2: r.level = min(5, r.level + 1); r.streak = 0
      r.interval_hours = ceil(prev_interval * r.ease)      # 1h→4h→1d→3d→7d→15d→毕业
      r.next_review_at = now + interval
      if r.level >= 5: r.next_review_at = now + 30d        # 维持性复习
  else:
      r.wrong_streak++; r.streak = 0
      r.level = max(0, r.level - 1); r.ease = max(1.3, r.ease - 0.20)
      r.interval_hours = 0.17                              # 10 分钟后会话内复现
      r.next_review_at = now + 10min
      upsert wrong_book_entries(kp)
  写回 mastery_records
```

- 错题移出：同一 kp 连续答对 3 次 → `cleared_at = now()`。
- 家长可 `POST /mastery/{kpId}/reset` 重置单个知识点。
- **复习积压保护**：到期条目 >100 时，`/practice/today` 只下发复习、暂停新学，并在家长端提示「建议设为复习日」。

### 4.5 护眼与时间控制

| 机制 | 前端 | 后端 |
| --- | --- | --- |
| 20-20-20 休息 | `useSessionTimer` 每 `rest_interval_min`（默认 20）弹全屏休息页，20 秒倒计时，可跳过（家长 PIN） | 仅提供设置值；不强制 |

| 可用时段 | 不在时段内不生成任务 | 同上校验 |
| 主题/字号/亮度 | Zustand 持久化，米黄纸感默认，日落自动切换深色，尊重 `prefers-reduced-motion` | 设置同步到服务端（跨设备一致） |

**倒计时权威性**：前端计时只用于体验；后端在 `finish` 与 `today` 时按 `started_at/answered_at` 真实时间计算，防止改本地时间绕过。

### 4.9 标准节奏基准线、真实速度与偏差统计

**核心原则：标准只作参照线，不做闸门。**

- **基准线**：建档案时按当前 `stage_code` 的顺序，把该阶段全部知识点按每日标准量（语文 6 字 / 数学 2 档 / 英语 5 词）铺成 Day 1…Day N，写入 `curriculum_plan`。孩子的 `planned_date` 一经生成就不再改动 —— 提前学、连学几课、整天只复习，都不影响这条线，这样才能算出真实偏差。
- **不限制次数与进度**：每日可学多课、可提前学下一日内容、可反复练同一内容；系统不锁课、不催促、不做"必须先完成 Day 3"。进度只由孩子实际掌握情况推进。
- **掌握判定**：某知识点首次达到 `level >= 3` 记为「掌握」（`mastered_at`）；level 0–2 只算接触过。
- **统计口径**

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| 真实速度 | 每日/每周实际新掌握数 | 与标准量对比 |
| 偏差 `deviation_days` | 当前日期 − 当前进度对应的 `planned_date`（正=落后，负=超前） | 家长一眼看进度快慢 |
| 累计曲线 | `cum_planned` vs `cum_actual`（分学科的累计掌握量） | 长周期趋势 |
| 重复次数 | ①当日对已学内容的重复练习量 `repeat_count` ②掌握单个知识点所用作答数 `attempts_to_master` ③跨天数 `repeat_days` | 反映巩固成本 |
| 学习效率 | `attempts_per_mastery = 掌握前的总作答数 / 掌握数`，配正确率一起读 | 低重复 + 高正确率 = 吸收快 |

- **报表呈现**（`GET /reports/{childId}/pace`）：计划 vs 实际双曲线、每日新掌握柱状图、重复次数柱状图、效率趋势（近 8 周滚动平均）。
- **文案纪律**：重复次数多不等于差，要与正确率组合解读；只做中性描述（如"这个字练了 5 次才掌握，在常见范围内"），不出现"落后""跟不上"等负向标签。

### 4.10 多孩对比（同一家长账号下）

- 接口：`GET /reports/compare?childIds=a,b&align=session|calendar`
- **对齐方式是关键**，否则比的是入学早晚而不是能力：
  - `align=session`（**默认**）：X 轴为「学习日序号」，各自从第一次学习起算 → 比的是学习速度，公平。
  - `align=calendar`：X 轴为自然日期 → 看真实时间轴上的进度（会受起始时间与中断影响）。
- **对比指标**（叠加曲线 + 指标表）：① 累计掌握量曲线（分学科）② 日均新掌握数（近 30 天滚动）③ 平均重复次数 / `attempts_per_mastery` ④ 正确率趋势 ⑤ 每日学习时长与学习天数 ⑥ 当前偏差天数。
- **呈现纪律**：只做并列与叠加，**不做排名、不做胜负文案**。差异用中性措辞表达（"姐姐识字重复次数更少，弟弟数学正确率更稳"），避免给孩子贴标签；家长端可随时关闭对比模块（默认开启）。

### 4.11 每日课时如何判定完成（决策：程序判定为主，家长确认为辅）

**采用混合制，默认全自动**：

| 环节 | 判定者 | 规则 |
| --- | --- | --- |
| 客观题（选择 / 填空 / 判断 / 连线 / 排序 / 描红完成度） | **程序** | 全题作答且正确率达标（默认 ≥60%）→ `completed_by=auto` |
| 主观项（跟读、朗读、亲子讨论题、纸质练习） | **家长** | 一键「完成」或打 1–5 分 + 一句评语 → `parent_score` / `parent_note`，**不计入客观正确率** |
| 兜底（纸上完成 / 口头完成 / 断网时完成） | **家长** | 手动标记完成 → `completed_by=parent`，计入完成度但标记来源，报表可区分 |

**为什么这样选**
1. 家长不必每题守着 —— 客观题程序判分最准，也最省事。
2. 主观项程序判不了，但占比小，家长点一下即可。
3. 防刷进度：今日徽章只认程序判定的客观完成；家长手动标记会留痕，报表能区分来源。
4. 想要更严格就开 `require_parent_confirm`（家长设置项，**默认关闭**）：开启后每日需家长点「确认完成」才点亮当日徽章。

**细节规则**
- 未达标不惩罚：显示"今天学了 8 分钟，明天继续"，不出现红色"未完成"。
- 跳过的题不计正确率，但计入完成度；完成度不足 100% 时按实际作答部分判定。
- 家长评分维度（简版，可跳过）：专注度 / 朗读口语 / 书写，各 1–5 星。

## 八、工程约定（编码时遵守）

| 项 | 约定 |
| --- | --- |
| 配置 | 全部环境变量，`config.Load()` 启动校验，缺失即 fail-fast；只提交 `.env.example`（占位值） |
| 日志 | `slog` JSON，字段含 `request_id`、`route`、`status`、`duration_ms`；**禁止记录密码/令牌/儿童隐私** |
| 错误 | `apperr.New(code, httpStatus, message)`；handler 只做映射；消息面向用户、中文可读 |
| 事务 | 多步写入（会话结束、打印补录、审核通过）在 service 层显式事务 |
| 迁移 | 每个里程碑一组 `NNN_xxx.up.sql / .down.sql`，禁止改已提交迁移 |
| SQL | sqlc 生成查询；复杂动态查询手写但仍在 repository 内；避免 N+1（批量取 kp、批量写 mastery） |
| 后台任务 | 走 `jobs` 表：幂等键 + 指数退避 + `max_attempts` 后进死信；不在请求处理器里跑长任务 |
| 缓存 | 进程内小缓存（阶段表、模板表）带 TTL；写后失效 |
| 测试 | 单测 mock repository；集成测试用真实 PG（事务回滚）；`go test ./...` 与 `go vet` 纳入每个里程碑 |
| 前端 | `npm run build` 必须过；`tsc --noEmit` 无错；禁止硬编码 API 地址；所有列表页有加载态/空态/错误态 |
| **Git 提交** | **每完成 1–2 项功能就提交一次**，不等整个里程碑结束；提交信息以 emoji 开头标识类型（见下表），正文用中文简述「做了什么 + 为什么」 |

**提交类型与 emoji 前缀（项目强制约定）**

| emoji | 前缀写法 | 用途 | 何时提交 |
| --- | --- | --- | --- |
| ✨ | `✨ feat:` | 新功能、新端点、新模块 | 每完成 1–2 项可验证的功能 |
| 🐛 | `🐛 fix:` | 缺陷修复 | 修完即提，说明根因 |
| 📝 | `📝 docs:` | 文档、设计说明、注释性调整 | 文档有实质变化时 |

- 审核：批量通过 3 条 `applied=3`，重复通过同一条 → 404（幂等），队列待审数 −3，`status=approved` 可查历史；
- 双语篇可取到中英两份正文（`slug=little-bear-s-honey-shop-779`），无配对 → 404；
- **导入器全量重跑幂等**：第二次 `plan_rows=0`、`review_items=0`、`story_pairs` 不新增，已发布状态不被回退。

**M2 期间的工程决策**

1. **sqlc 落地范围**：读查询用 sqlc；批量导入不走 sqlc（生成的是单行语句，1.9 万篇按单行写会多几个数量级的往返；COPY 又带不了 `ON CONFLICT`），改用手写多行 upsert + 冲突键去重。
2. **生成代码入库**（`internal/dbgen`），构建不依赖 sqlc 二进制；`schema` 只列 `*.up.sql`，避免回退脚本里的 `DROP` 干扰解析。
3. **字典即发布，采集待审**：汉字 / 组词 / 英语词由自有管线产出，导入即 `published`；故事为采集内容，一律 `pending` 进审核队列。
4. **不宜内容双保险**：`unsafe_hits` 记录命中的不宜词，`suitable` 决定孩子端是否默认屏蔽 —— 即使家长误批一篇，孩子端仍看不到。
5. **基准线锚点**取孩子档案创建日，`planned_date = 建档日 + (day−1)`；`unique(child_id, kp_id)` + `DO NOTHING` 保证补数据后重跑只追加、不改已铺的天序号。

**九种题型**：`choice_text` `choice_image` `choice_audio` `fill_blank` `match` `order` `trace` `say` `math_param`。
新学汉字以描红为主（先认字形），复习以识别类为主（考提取）；英语新词先听音、复习考形义对应；
数学只出参数化题；故事只出跟读。干扰项一律取同阶段 / 同级别的其它知识点。

**对设计的三处有意偏离**

1. `interval_hours` 用 `numeric(10,4)` 而非 `int`：§4.4 答错要写 0.17 小时（10 分钟复现），整型存不下。
2. 复习间隔按 level 阶梯取（1h / 4h / 1d / 3d / 30d），`ease` 只在 ±30% 内微调。
   设计里「1h→4h→1d→3d→7d→15d」与「level≥5 时 30d」在 7d/15d 上冲突，取显式代码行的语义：
   level 5 是毕业档直接跳 30 天。
3. `session_items` 拆 `question_snapshot` 与 `answer_key` 两列：题面要能复现报表，
   答案绝不能跟着题面下发，混在一列里只能靠序列化时手挑字段，容易漏。

**验收结果**（`server/tmp/smoke_m3.py`，71 项全通过）

- 同一 `(template, count, seed)` 两次生成的题目完全一致，换 seed 则不同；
- 答错后 `next_review_in_minutes = 10`（会话内复现）且进错题本；重复作答同一题 409；
- 语文 / 英语 / 数学三科各能完整走完一次会话；
- 家长打分后客观正确率不变；描红题 `is_correct` 为 `null`（不计正确率）；
- 越权 404、参数非法 422、评分越界 422。

**踩过的坑**

- `knowledge_points.ref_id` 在 M2 从未回填（只补了反向的 `hanzi.kp_id`），
  组卷的 JOIN 永远匹配不到 → 新增导入步骤 `refs` 幂等回填（`cmd/importer -only refs`）。
- 孩子的 `stage_code` 是语文阶段，拿它过滤数学知识点（M1–M5）会一条都选不出来 → 只对语文生效。
- `0.17` 小时实际是 10.2 分钟，取整后显示成 11 分钟 → 答错间隔改用 `10 * time.Minute` 单独定义。
